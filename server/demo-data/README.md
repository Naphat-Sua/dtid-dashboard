# ข้อมูลสาธิตชุดเพิ่มเติม 184 คดี (รวมเป็น 220 คดี)

ต้นฉบับ: `DTID_demo_184_cases.xlsx` (ข้อมูลสมมุติทั้งหมด) ส่วนตัวแปลงคือ `scripts/appendDemoXlsx.py`
เพิ่มข้อมูลอย่างเดียว ไม่ได้ลบ ล้าง หรือแก้ระเบียนเดิม และไม่ได้แก้โค้ดระบบ

## โหมดสาธิตบนเว็บ (LOCAL)

หน้าเว็บโหมดสาธิตอ่านข้อมูลจาก `src/data/mockData.js` (ไม่ได้อ่านฐานข้อมูล) สคริปต์จึงต่อท้ายระเบียนใหม่
เข้าไปในแต่ละอาร์เรย์ของไฟล์นี้ โดยใช้ ID ตั้งแต่ 1001 ขึ้นไป (ของเดิมสูงสุดคือ 320)

| | เดิม | เพิ่ม | รวม |
|---|---:|---:|---:|
| คดี | 36 | 184 | **220** |
| บุคคล | 14 | 107 | **121** |
| ของกลาง | 34 | 202 | **236** |
| ความสัมพันธ์ | 15 แถว / 15 คู่ | 65 แถว / 64 คู่ | **80 แถว / 79 คู่** |
| บุคคล-คดี | 53 | 213 | 266 |

คู่ A01–A02 มีความสัมพันธ์ 2 ประเภท (Boss-Subordinate และ Financial) จึงนับได้ 79 คู่จาก 80 แถว
ช่อง Edges ในหน้า Network นับเป็นแถวจึงแสดง 80

ตรวจแล้วบน build จริง (ไม่มี backend): กดเข้าแบบสาธิตแล้วการ์ดแสดง "of 220 total"
หน้า Network แสดง Nodes 121 / Edges 80 แม้เบราว์เซอร์จะยังมีแคช 36 คดีเดิมใน localStorage อยู่
เพราะการเข้าแบบสาธิตจะโหลด mockData ใหม่ทุกครั้ง

## ฐานข้อมูล (โหมด DB) แบบเพิ่มอย่างเดียว

```bash
# 1) Admin > Import Cases from CSV → demo-data/cases_184_import.csv   (184 แถว)
# 2) ตารางที่ระบบไม่มีหน้านำเข้า (บุคคล ที่พัก ของกลาง บุคคล-คดี ความสัมพันธ์)
psql -U postgres -d dtid_dashboard -f demo-data/related_184.sql
```

`related_184.sql` มีแต่คำสั่ง INSERT โยงคดีด้วย case_number และโยงบุคคลด้วยเลขบัตร ถ้ารันซ้ำก็ไม่เกิดข้อมูลซ้ำ
**ห้ามรัน** `db:reset` หรือ `db:seed` เพราะจะสร้างฐานใหม่หรือลงข้อมูลชุดเก่า

ผลทดสอบบนฐานที่มี 36 คดีเดิมอยู่แล้ว: นำเข้าได้ 184/184 แถว ไม่มี error ได้คดีรวม 220
ค่า hash ของ 36 แถวเดิมก่อนและหลังนำเข้าตรงกัน และเมื่อรัน SQL ซ้ำ จำนวนแถวไม่เปลี่ยน

## การแปลงค่าให้ตรงกับระบบ

| คอลัมน์ | ในไฟล์ | ในระบบ |
|---|---|---|
| สถานะบุคคล | Wanted (4) | Suspect (เก็บค่าเดิมไว้ใน Notes) |
| | Surveillance (3) | Active (ป้าย "เฝ้าระวัง") |
| เพศ | ชาย / หญิง | M / F |
| ประเภทความสัมพันธ์ | Courier | Courier-Handler |
| ชนิดยา | ยาบ้า / ไอซ์ / ยาอี / เคตามีน | Methamphetamine / Crystal Meth / Ecstasy / Ketamine |
| หน่วย | เม็ด / ก. / กก. | pills / g / kg |
| อายุ | age | ไม่มีช่องอายุ จึงเก็บไว้ใน Notes (DateOfBirth = null) |
| arrest_date | YYYY-MM-DD | YYYY-MM-DDT00:00:00 (ในโหมดสาธิต) |

ค่าอื่น ๆ (case_type, สถานะคดี, location_type, risk_level, role, strength) ตรงกับระบบอยู่แล้ว
ส่วนเลขบัตรรูปแบบ 99999… ระบบไม่ได้ตรวจ checksum
